## Fokkus IDE 1.4.0 — Modos de ejecución, aprobaciones en el chat y revisión de PRs sin credenciales

### Nuevo
- **Modos de ejecución que funcionan de verdad** (Settings > Workspace). El modo elegido se guarda y se envía al agente líder como instrucción crítica en cada mensaje del chat, incluidos los prompts que llegan desde el Kanban y desde Pull Requests:
  - **Manual:** el agente líder pide tu aprobación antes de cada interacción con el código, desde el plan de implementación hasta cada cambio crítico.
  - **Automático:** el líder pide al PM un plan según el estado del proyecto y delega cada etapa al área correspondiente, sin interrupciones. Solo consulta ante operaciones irreversibles.
  - **Plan de implementación:** el PM genera un plan y lo apruebas en el chat. Si lo apruebas, el equipo trabaja sin más interrupciones. Si lo rechazas, se detiene para iterar contigo.
- **Aprobaciones dentro del chat:** los agentes tienen una herramienta, `fokkus_request_approval`, para pedir tu visto bueno antes de una operación crítica. La solicitud aparece como una tarjeta con título, resumen y nivel de riesgo, y los botones **Aprobar** / **Rechazar** (con motivo opcional). Solo se puede responder la solicitud vigente. Las anteriores muestran si se aprobaron, se rechazaron o quedaron sin respuesta, y ese estado se conserva al recargar.
- **Indicador del modo activo** en la barra del chat. Al hacer clic se abre la configuración.

### Corregido
- **"Pedir revisión a agentes" ya no pide credenciales** (#21): el prompt obtiene el diff del PR por la API de GitHub usando el token de la integración (`$GITHUB_TOKEN`), en vez de un `git fetch` sin autenticar que abría KWallet o SSH askpass. Los agentes reciben el token (de la variable de entorno o de `~/.fokkus/github.json`) y git se ejecuta con los prompts de credenciales desactivados. El token nunca se escribe en el prompt ni en el historial. También aplica a workspaces en WSL desde Windows.
- Iconos que no se veían con Font Awesome 4.7 (botón Compactar, modo Manual y algunas pestañas de Settings).

### Eliminado
- **Workspace Tree** en Settings > Workspace: el visor de diff (redundante con Source Control), los botones Approve (Commit) / Reject (Discard), que hacían `git add . && git commit` o `git reset --hard && git clean -fd` sobre todo el repo, y el botón "Ejecutar Prueba".

### Versionado
- Todos los paquetes (lerna, aplicaciones y extensiones) pasan a 1.4.0.
