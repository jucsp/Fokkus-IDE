## Fokkus IDE 1.5.0 — Pull Requests de Bitbucket en Source Control (solo lectura)

### Nuevo
- **Bitbucket Pull Requests en Source Control** (#6): nueva sección junto a CHANGES, GRAPH y la de Pull Requests de GitHub, con la misma experiencia de uso:
  - **Vista global:** sin filtro muestra los PRs abiertos de todos tus repositorios de Bitbucket, del más reciente al más antiguo.
  - **Filtro por repositorio:** se guarda por workspace. El botón **Detectar** lee el `origin` de la carpeta abierta (`git@bitbucket.org:…`, `https://…@bitbucket.org/…`, `ssh://…`).
  - **Filtro por estado:** Abiertos, Merged, Declinados, Superados o Todos. También se puede buscar por repo, id o título.
  - **Detalle del PR:** descripción sanitizada y archivos modificados (diffstat con +/−).
  - **Errores por repositorio visibles:** si un repo falla (por ejemplo, 403 porque el workspace fue desactivado), se muestra en un aviso y el resto de repos se sigue cargando.
- **«Pedir revisión a agentes»** envía al chat de Fokkus Team un prompt de code review que obtiene el diff por la API REST con `curl` GET (`/diff`, `/diffstat` y `/src/<hash>/<ruta>`). La credencial se referencia solo por el nombre de la variable (`$BITBUCKET_TOKEN_<CLAVE>` o `$BITBUCKET_USERNAME:$BITBUCKET_APP_PASSWORD`) y su valor nunca aparece en el prompt ni en el historial.
- **Credenciales para los agentes:** las variables `BITBUCKET_*` de `~/.bitbucket_credentials.env` se inyectan en el entorno de los agentes CLI (también en WSL mediante `WSLENV`). Nunca se sobrescribe una variable que ya exista en el entorno.

### Modo estrictamente de solo lectura
- El backend hace todas las llamadas desde un único punto que solo permite `GET` contra `api.bitbucket.org`. La paginación solo sigue enlaces `next` del mismo origen.
- La interfaz no tiene ninguna acción para aprobar, mergear, declinar ni comentar. El prompt de revisión prohíbe a los agentes `git fetch`/`clone`/`pull`, cualquier método distinto de GET y cualquier acción de escritura sobre el PR.
- Los tokens nunca viajan al frontend: la interfaz solo recibe el nombre de la variable.

### Configuración (`~/.bitbucket_credentials.env`)
```
BITBUCKET_USERNAME=tu_usuario
# Repositorio: <slug> (<workspace>)
BITBUCKET_TOKEN_<CLAVE>=<repository access token>
# Opcional: repo explícito para un token, o app password para descubrir tus repos
BITBUCKET_REPO_<CLAVE>=<workspace>/<slug>
BITBUCKET_APP_PASSWORD=<app password>
```
El comentario `# Repositorio:` admite texto adicional después del paréntesis.
