## Fokkus IDE 1.7.2 — Bandeja Pre-Kanban: reglas de auto-descarte aprendidas y respuesta al cliente con revisión humana

### Nuevo
- **Aprendizaje activo de descarte (Feedback-driven Triage)** (#28): cuando descartas una solicitud indicando un motivo, la Bandeja aprende una regla y descarta sola las solicitudes nuevas que se le parezcan.
  - La regla se infiere del remitente (email y dominio) y de hasta 8 palabras clave del asunto original y del motivo. Se ignoran las palabras de menos de 3 letras y las palabras vacías. El remitente y las palabras clave se combinan con AND: tienen que coincidir todos.
  - Las reglas se guardan en `~/.fokkus/triage-feedback.json`. Si el archivo está dañado, se aparta y las reglas empiezan vacías. Cada regla cuenta cuántas solicitudes descartó (hits).
  - Las solicitudes nuevas que cumplen una regla entran como descartadas, con el badge **«Auto-descartado por IA»**. Su tooltip muestra el motivo.
  - Nueva sección colapsable **«Reglas de auto-descarte»** y botón **«Reglas»** en la barra de Solicitudes. La sección se abre sola con el filtro Descartadas. Muestra las palabras clave, el remitente o dominio, el motivo, la fecha y los hits de cada regla, y deja revocarla (con confirmación).
  - Si restauras o descartas a mano una solicitud auto-descartada, pierde la marca de auto-descarte.
- **Borrador de respuesta al cliente con revisión humana (Human-in-the-Loop)** (#29): al aprobar una solicitud, Fokkus redacta una respuesta en español para quien la envió, con el identificador y el enlace del ticket creado.
  - Tras aprobar se abre un modal con el destinatario, el ticket, el asunto (editable solo en Gmail) y el cuerpo editable. Puedes elegir **Enviar**, **Copiar al portapapeles** u **Omitir**. Esc o un clic fuera del modal lo cierran.
  - **Slack:** la respuesta se publica en el mismo hilo (`chat.postMessage` con `thread_ts`).
  - **Gmail:** la respuesta se envía en el mismo hilo. Si el token no tiene permiso de envío (`gmail.send` o `gmail.modify`), se deja un borrador en Gmail. Si tampoco se puede crear el borrador, la solicitud queda sin responder y puedes reintentar o copiar el texto.
  - Las tarjetas aprobadas muestran el badge **«Respuesta enviada»** o **«Borrador en Gmail»** con la hora, o el botón **«Enviar respuesta al cliente»** si todavía no se respondió.
  - «Copiar al portapapeles» solo registra la hora de la copia y deja enviar la respuesta después desde el IDE.

### Seguridad
- Del asunto se quitan los saltos de línea (CR/LF) para que no se puedan inyectar cabeceras RFC 2822 en el correo.
- Un candado por solicitud impide enviar la misma respuesta dos veces si se pulsa Enviar dos veces seguidas.
- La lista de URLs permitidas para HTTP solo agrega tres endpoints `POST`: `https://slack.com/api/chat.postMessage`, `https://gmail.googleapis.com/gmail/v1/users/me/messages/send` y `…/users/me/drafts`. El resto de Slack y Gmail sigue siendo solo lectura.

### Limitaciones conocidas
- Para responder en Slack, el token necesita el permiso `chat:write`. Con una sesión web (`xoxc-` + cookie `d`) se usan tus permisos de usuario.
- Las reglas de auto-descarte comparan palabras exactas, no sinónimos: un asunto redactado de otra forma no las activa.
- No se ha probado todavía contra Slack ni Gmail reales: la QA usó pruebas unitarias.
